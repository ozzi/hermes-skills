# Отчёт о расходе и балансе с озвучкой

## When to Use

«Скажи, сколько токенов сожгли за вчера и сколько денег осталось», «озвучь расход по провайдерам»,
«пусть колонка каждый день говорит остаток баланса». Задача = **собрать цифры из API провайдеров →
сложить русскую фразу → отдать на озвучку**. Сама озвучка — отдельная задача: BluOS через
`bluos-announce`, Яндекс Станция через `alice-announce`.

## Ключи: два разных класса, права гранулярно не режутся

У OpenRouter **нет** ключа «только на чтение баланса»: права определяются классом ключа.

| Ключ | Где создать | Что может | Чего не может |
|---|---|---|---|
| обычный (inference) | `/keys` | вызовы моделей, `GET /api/v1/key` (расход только своего ключа) | баланс аккаунта, аналитика |
| **management** | `/settings/management-keys` | ВСЁ админское: ключи, BYOK, guardrails, workspaces, `/credits`, `/activity`, `/analytics/*` | вызовы моделей (completions он не обслуживает) |

Management-ключ **unscoped** — это документированное поведение, а не настройка. Единственное
реальное ограничение — **срок жизни** (фиксируется при создании и потом не меняется: ротация =
создать новый + удалить старый). Guardrails (бюджеты, allowlist моделей) к management-ключу не
применяются: они про inference-трафик.

Поэтому разделение ролей делается **двумя ключами**: management живёт только в окружении отчётного
скрипта, inference — у клиентов; утечка любого не даёт второго. Ключ хранится в `$HERMES_HOME/.env`
(права 600) под своим именем и приходит процессу как переменная окружения — в конфиг-файлы и в
репозиторий он не попадает.

## Данные: какие ручки что дают

| Ручка | Что отдаёт | Ключ | Точность окна |
|---|---|---|---|
| `POST /api/v1/analytics/query` | `total_usage` ($), `tokens_total`, `tokens_prompt`, `tokens_completion`, `request_count` по `granularity: hour/day` | management | **произвольный ISO-интервал** → точные локальные сутки |
| `GET /api/v1/activity?date=YYYY-MM-DD` | то же с разбивкой по модели/эндпоинту | management | только **завершённые UTC-сутки**, до 30 дней; сегодняшняя дата → 400 |
| `GET /api/v1/credits` | `total_credits`, `total_usage` → баланс = разница | management | мгновенно |
| `GET /api/v1/key` | `usage*` (по этому ключу), `limit_remaining`, `budgets` | любой | мгновенно |

Метрики и измерения для запроса — в `GET /api/v1/analytics/meta`. Числа в ответе приходят
**строками** — приводить явно.

### Провайдер без ручки расхода: баланс у него, токены и трата — из журнала шлюза

У DeepSeek **нет** ручки расхода: платформа не отдаёт ни историю трат, ни счётчики токенов — ни в
API, ни в консоли. Такой источник собирается из двух мест, и это общий шаблон для любого
провайдера без usage-API, чей трафик ходит через LiteLLM:

| Часть | Откуда | Ключ |
|---|---|---|
| `balance` | `GET https://api.deepseek.com/user/balance` → `balance_infos[].total_balance` (валюту брать из того же ответа — бывает `CNY`) | `DEEPSEEK_API_KEY` |
| `spend`, `tokens`, `requests` | SpendLogs шлюза: `GET /spend/logs/v2?start_date=&end_date=&page=&page_size=`, строки фильтруются по `custom_llm_provider` | `LITELLM_ADMIN_KEY` |

Фильтр **по провайдеру**, а не по имени модели: под одним алиасом живут разные ветки маршрута
(прямой провайдер на одном `order`, агрегатор на другом), и только `custom_llm_provider` в строке
журнала отделяет расход одной ветки от соседней. Строки журнала несут `spend`, `total_tokens`,
`request_count`-эквивалент (считается числом строк), поэтому обе цифры берутся из одного прохода.

Что нужно снаружи: ручка журнала должна быть **выставлена наружу прокси** (фасад по умолчанию
отвечает на неё `404`) — точечно по методу и пути, как это делается для других админских ручек,
и с ограничением по адресам. Формат дат у ручки не документирован и зависит от сборки, поэтому он
вынесен в конфиг (`ledger.date_format`): первый живой ответ уточняет его правкой конфига, а не кода.

Блок `ledger` **необязателен**. Без него (или когда ручка недоступна) источник обязан отдать
только баланс, написать строку в stderr и не тронуть остальные источники — фраза просто не
упоминает расход. Молчаливая подмена расхода нулём или отказ всего отчёта из-за одной ручки — оба
варианта хуже.

## Периоды и календарь озвучки

Ручные периоды: `yesterday` (прошедшие локальные сутки) · `today` · `week` (с понедельника) ·
`month` (с 1-го числа). Границы считаются в **локальной зоне машины**, окно уходит в API в UTC —
поэтому «вчера» = ровно `00:00–00:00` местного, а не UTC-день.

Режим `auto` — для регулярного задания:

- **в выходные озвучки нет** (и в датах из `skip_dates` — там перечисляются праздники);
- **в первый рабочий день после выходных** отчёт покрывает прошедшие выходные: в понедельник окно
  начинается с пятницы, и фраза это проговаривает («за пятницу и прошедшие выходные»,
  «за прошедшие выходные»);
- пропущенные дни **не теряются**: окно тянется от конца последнего удачно озвученного отчёта
  (`state.json`), а не от «вчера». Пропуск в несколько дней даёт «за последние N дней»
  (глубина догона ограничена двумя неделями);
- состояние двигается **только после успешной озвучки** — иначе сбой колонки съел бы отчёт за день;
- повторный запуск в тот же день молчит.

## Инструмент

`scripts/usage_report.py` — только stdlib. Печатает фразу; с `--announce` отдаёт её скрипту
озвучки навыка `bluos-announce`.

```bash
usage_report.py                          # вчера, источники из конфига, напечатать
usage_report.py week --announce          # неделя + озвучить
usage_report.py auto --announce          # календарный режим (для задания)
usage_report.py month --convert RUB      # месяц + пересчёт траты по курсу ЦБ
usage_report.py today --json             # машинный вывод (точные числа)
usage_report.py auto --dry-run --now 2026-10-19T08:00:00+04:00   # проверить окно без сети/озвучки
usage_report.py --list-sources
```

Токены в фразе **округлены до миллионов** («двести восемьдесят восемь миллионов токенов»): на слух
нужен порядок, а не каждая единица; точное значение остаётся в `--json`. Деньги произносятся как
есть — «шесть долларов три цента». Нулевая трата проговаривается как «расхода не было», а не
«потрачено ноль долларов».

## Ответ на разовый вопрос в чате

«Сколько потрачено за сегодня и какой баланс?» — это период `today`, подставлять его вручную не
нужно:

```bash
usage_report.py today            # расход с начала суток + остаток баланса на сейчас
usage_report.py week --json      # если нужны точные числа, а не словами
```

Озвучка на колонке — отдельное действие: без `--announce` скрипт только печатает. Отвечая в чате,
цитируй фразу из вывода; проси озвучить, только если пользователь этого хочет.

**Окно и баланс живут в разных временах.** Расход — за закрытое или текущее окно, баланс — снимок
на момент запуска. Поэтому «за вчера потрачено столько-то, остаток сейчас такой-то», а не «осталось
за вчера». Две озвучки, разделённые минутами, дают одинаковый расход и разный баланс — это
ожидаемое поведение, а не расхождение: расход идёт непрерывно, и цифру в отчёте за прошедшие сутки
можно сверить повторным запуском (она совпадает до знаков после запятой).

## Как добавить провайдера

Точка расширения — реестр `SOURCES`: новый источник = **одна функция** с декоратором
`@source(имя, имя_env_переменной, заголовок)`, возвращающая словарь с любым подмножеством полей
(`spend`, `tokens`, `balance`, `requests`, `currency`). Фраза сама не упоминает отсутствующее, а
упавший источник не ломает остальные: его ошибка уходит в stderr и в `errors` JSON-вывода.

```python
@source("deepseek", "DEEPSEEK_API_KEY", "Дипсик")
def collect_deepseek(cfg, window, now):
    ...                                  # window = (start, end) в локальной зоне
    return {"title": "Дипсик", "currency": "USD", "balance": 12.34}
```

Правило: **ключ читать только из окружения процесса**; адреса, набор источников и путь к скрипту
озвучки — из локального конфига, где секретов нет.

## Настройка

Конфиг — `~/.config/hermes-usage-report/config.json` (меняется `--config` или `USAGE_REPORT_CONFIG`),
состояние режима auto — рядом (`--state-file`, `USAGE_REPORT_STATE`). Пишется командой, не руками:

```bash
usage_report.py --write-config ~/.config/hermes-usage-report/config.json --source openrouter \
  --announce-script ~/.hermes/scripts/hermes_announce.py --convert RUB
```

```json
{
  "sources": {"openrouter": {"enabled": true, "title": "Опенроутер"},
              "deepseek": {"enabled": true, "title": "Дипсик",
                           "ledger": {"enabled": true, "key_env": "LITELLM_ADMIN_KEY",
                                      "base_url": "https://llm.outzzz.tech",
                                      "provider": "deepseek"}}},
  "convert": "RUB",
  "skip_dates": ["2027-01-01", "2027-01-07"],
  "announce": {"script": "~/.hermes/scripts/hermes_announce.py", "args": ["--volume", "0.3"]}
}
```

Приоритет по источникам: `--source` → конфиг → `openrouter`. Пересчёт по курсу — публичный XML
ЦБ РФ (без ключей), отдельным предложением.

## Доставка токена озвучки: своё имя обязательно

Ядро вырезает `HASS_TOKEN`/`HASS_URL` из окружения **всех** дочерних процессов (terminal,
execute_code, cron-скрипты) — так HA вынесли из ядра в catalog-плагин
(`plugin-catalog/homeassistant.yaml` объявляет их как `requires_env`). Санитайзер режет
**только** объявленные имена, поэтому озвучка обязана ходить под **своим** именем:

- значение кладётся в `$HERMES_HOME/.env` под кастомным именем (`ANNOUNCE_HA_TOKEN`);
- имя передаётся скрипту озвучки через `announce.args: ["--token-env", "ANNOUNCE_HA_TOKEN"]`;
- `terminal.env_passthrough` **не нужен**: планировщик перечитывает `.env` перед запуском
  no_agent-скрипта, а `_filter_secret_env` отбрасывает лишь блок-лист — незаявленное
  кастомное имя доезжает до ребёнка само. Рестарт gateway для этого тоже не нужен;
- `env_passthrough` с именем `HASS_TOKEN` отвергается по построению (санитайзер не даёт
  операторскому конфигу снять пломбу GHSA-rhgp-j443-p4rf) — не пытайся так обойти.

Симптом молчаливого отказа: отчёт считается, а строка лога содержит
`озвучка: rc=1 ok=False нет HASS_TOKEN в окружении`. Тот же дефект бьёт по **любому**
вызову `hermes_announce.py`/`alice_say.py` из сессии агента, а не только по cron.

## Доставка правок в репозиторий

Навык установлен как tap из `ozzi/hermes-skills`: **папка навыка — это чекаут репозитория, а не
место для правок**. Правка в ней исчезнет при следующем `hermes skills install`, включая правку,
которой починили сбой. Порядок переноса и грабли выкладки (нейтральные адреса, пуш через URL
с токеном, `diff` после переустановки) — в разделе «Публикация навыка» навыка `bluos-announce`.

## Регулярный запуск

Задание **без модели** (`no_agent`), скрипт-обёртка `usage_report_announce.sh`: она вызывает
`usage_report.py auto --announce`, пишет строку в `$HERMES_HOME/cron/output/usage-report.log` и
**молчит при успехе** — пустой stdout значит, что задание ничего не отправило, а любой вывод
становится аварийным алертом. Путь задания — имя файла в `$HERMES_HOME/scripts/` (абсолютные пути
и `~` валидатор отклоняет).

Форма задания: cron `0 10 * * 1-5` — будни 10:00 (суббота и воскресенье закрыты и расписанием, и
режимом `auto` — расписание страхует от лишнего запуска, `auto` не даёт произнести пустое окно).
Доставка: `deliver=local` (в чат задание не пишет, фраза уходит голосом, строка — в лог),
`failure_deliver=origin` — алерт о сбое приходит в чат владельца. Выход задания — «тишина =
успех», поэтому `local` теряет только строки лога, а не сигнал о сбое.

**Прогонять боевой скрипт вручную нельзя** — `run` у этого задания произнесёт отчёт вслух с
настоящим окном и сдвинет состояние догона. Проверка выкатки: подменить `script` задания на
временную пробу, которая печатает только наличие имён окружения (без значений) и `id -un`,
выполнить `run`, затем вернуть боевой скрипт. Так проверяются обе вещи сразу — что ключ доезжает до
дочернего процесса и под каким пользователем/интерпретатором он запускается.

Что учесть при выкатке: планировщик запускает скрипт с вычищенным окружением, где часть
провайдерских имён ключей вырезается — **своё, кастомное имя переменной** проходит. `python3` в PATH
такого процесса — управляемый Hermes интерпретатор (venv из каталога installs), а не системный,
поэтому скрипт обязан обходиться stdlib и не зависеть от системных пакетов; проверяй его тем же
интерпретатором, а не только своим. Первый запуск проверяй по логу и по состоянию плеера, а не по
коду ответа.

## Pitfalls

- **`/activity` не умеет локальные сутки и сегодняшний день** (сегодняшняя дата → 400). Нужны
  сегодня/локальное «вчера» — только `analytics/query`.
- **Числа в `analytics/query` приходят строками.** Сложение без приведения даёт
  `TypeError: unsupported operand type(s) for +: 'int' and 'str'`.
- **`limit_remaining` у management-ключа пуст** (`null`) — остаток баланса аккаунта берётся только из
  `/credits` как `total_credits - total_usage`.
- **Баланс — на момент запуска**, а не на конец периода: формулируй «остаток баланса», а не
  «осталось за сутки».
- **Свежий час может не попасть в агрегат.** Гранулярность запрашивай `hour`: тогда окно честно
  покрывается часами и `today` не выглядит пустым.
- **`auto` и ручные периоды — разные вещи.** `yesterday` в ручном запуске всегда предыдущие сутки;
  календарная логика (выходные, догон) живёт только в `auto`.
- **Пропущенные дни закрывает состояние, а не скрипт-обёртка.** Обёртка не должна «дожимать»
  прошлые периоды: она сломает догон и озвучит один и тот же расход дважды.
- **Смена дня на границе озвучки.** Отчёт за вчера в 08:00 и «за сегодня» в том же запуске —
  разные окна; не смешивай их в одной фразе.
- **Источник без части полей — норма.** Не заставляй фразу произносить нулевой расход там, где API
  периода не умеет (у DeepSeek своей ручки расхода нет — расход и токены берутся из журнала шлюза,
  см. раздел выше). Если ручка журнала недоступна, правильный ответ — баланс без расхода и строка в
  stderr, а не выдуманное число.
- **Расход нельзя считать по разнице баланса.** Баланс двигают не только траты, но и пополнения:
  пара «прошлый снимок минус текущий» даёт то ноль, то отрицательное число. Единственный источник
  токенов и трат — журнал запросов шлюза.
- **Голос TTS привязан к модели за алиасом**, а не к алиасу: при смене апстрима старый голос даёт
  `400 Unknown voice` и выглядит как поломка всего пайплайна.
- **Озвучка — побочный эффект, а не проверка.** Тестовый прогон с `--announce` звучит на живой
  акустике в комнате и прерывает то, что играло: чтобы проверить окно и данные, используй
  `--dry-run` и `--json`; озвучивай только по прямому запросу пользователя и предупреждай, что
  проверка будет слышна.
- **Ручной `run` боевого задания — такое же действие**, как озвучка по расписанию; для проверки
  выкатки подменяй `script` задания на пробу, а не запускай боевой скрипт.
- **Озвучку проверять по состоянию плеера**, а не по коду возврата: у BluOS нет announce, и очередь
  возвращается на ту же секунду только при корректном восстановлении.
- **Токен озвучки под блокированным именем молчит на всех поверхностях сразу.** Отчёт при этом
  считается и алерт приходит в чат — выглядит как «сломалась только колонка». Первым делом
  сверь имя переменной в `announce.args` с блок-листом ядра, а не ищи проблему в HA или TTS.
- **Обёртка в дереве навыка и боевая копия расходятся.** `skills/<навык>/scripts/*` и
  `$HERMES_HOME/scripts/*` — это два независимых файла; проверку `ok=True` легко поправить
  только в одной. После любой правки сверяй их `diff`-ом.

## Verification

1. Числа: сумма `analytics/query` за UTC-сутки должна совпасть с `/activity` за тот же день
   (проверено: `5.707036` против `5.707036`).
2. Календарь: `auto --dry-run --now <ISO> --state-file <временный>` для среды, субботы,
   понедельника без состояния, понедельника с состоянием «пятница», повторного запуска и догона —
   окно и фраза должны совпасть с ожидаемыми (будни сдвигаются на сутки, понедельник забирает три).
3. Озвучка: у скрипта озвучки непустой `after`, тот же `song`/`secs`, что и до объявления.
4. Регулярный запуск: одна строка в `$HERMES_HOME/cron/output/usage-report.log` с `rc=0` и полным
   текстом фразы; stdout задания пуст, плеер остался в прежнем состоянии (`state`, `song`, `secs`).
5. Доезд окружения: проба-скрипт показывает, что кастомное имя ключа есть в дочернем окружении,
   а боевой скрипт отрабатывает на том же интерпретаторе, что даёт задание.
