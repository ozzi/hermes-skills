# Внешний вход (HDMI ARC / optical) на BluOS

## Сигнатура в `/Status`

Плеер на внешнем входе:

```xml
<state>connecting</state>          <!-- бывает и play; при выключенном телевизоре держится часами -->
<service>Capture</service>
<inputId>input4</inputId>
<inputTypeIndex>arc-1</inputTypeIndex>
<title1>HDMI ARC</title1>
<song>0</song><secs>0</secs>
<!-- тегов serviceName и totlen нет -->
```

Своя очередь: `<service>LocalMusic</service>`, `<serviceName>Library</service>`, `<song>N</song>`,
`<totlen>` задан. Идёт объявление по URL: `service=http` (или пусто), `serviceName` пуст,
`totlen` ≈ длине mp3.

**Пустой `serviceName` сам по себе ничего не значит** — он пуст и у входа, и у объявления.
Внешний вход узнаётся по `service=Capture` (или hdmi/optical/analog/bluetooth, если прошивка так
называет) вместе с `inputId`.

## Правила

- **`state=play/connecting` на входе ≠ звук.** Считать «играло» только при `state` ∈ {play, stream}
  **и** непустом `serviceName`, **и** `service` не из списка входов.
- **`/Play?seek&id` на входе — это переключение на очередь с включением музыки**, а не «продолжить
  с места». Отсюда и симптом «после объявления играет музыка, хотя никто не нажимал».
- **`/Stop` с входа уводит на очередь** (наблюдалось `song` 0 → 2), вход не возвращает. Остановка
  объявления и возврат на вход — две разные операции, вторая требует решения человека.
- **Возврат на вход:** `GET /Play?inputId=<inputId>` (POST проходит тоже). Вход приходит в
  `connecting`, то есть выбор входа всегда его включает; прежний `pause` возвращается отдельным
  `/Pause` уже после переключения.
- **`/Pause` на самом входе принимается** (`state=pause` и держится) — значит прежнее состояние
  «телевизор выключен» восстанавливается: переключить вход, затем `/Pause`.
- **Порядок возврата важен:** сначала вернуть очередь на прежнюю секунду и поставить паузу
  (`/Play?seek&id` + `/Pause`), только потом `/Play?inputId=<inputId>`. Наоборот нельзя: `/Play?seek&id`
  после переключения снова утащит вход на очередь.
- **Возврат входа — поведение по умолчанию** (`restore_input()` в `hermes_announce.py`, общий для
  обоих скриптов навыка): человек оставил плеер на этом входе, и объявление не должно его менять.

## Что проверено, а что нет

Проверено чтением `/Status` и командами на живом плеере: сигнатура входа, уход на очередь после
`/Stop`, возврат через `/Play?inputId`, приём `/Pause` на входе, доигрывание короткого потока при
`/Stop` у конца. Полный сценарий объявления прогнан дважды на живой колонке при `--volume 0`
(беззвучно): вход `stream` (телевизор включён) → после объявления `Capture/input4` + `connecting`,
очередь на прежней секунде и на паузе; вход `pause` (телевизор выключен) → после объявления
`Capture/input4` + `pause`, то есть ровно как было. Отчёт скрипта подтверждает: `input_restored=true`,
во втором случае `input_paused=true`.

Не проверено: дойдёт ли вход из `connecting` до `stream` сам, когда телевизор снова отдаст звук
(в тихом прогоне телевизор молчал), и не закрывается ли при этом меню телевизора. Проверять по слуху
на обычном объявлении, а не синтетикой.
